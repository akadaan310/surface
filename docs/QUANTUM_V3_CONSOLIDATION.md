# Quantum Oracle × PHANTOM V3 consolidation into Surface

## Result and scope

The supplied `QUANTUM_ORACLE_PHANTOM_V3_N_ATLAS.zip` is **byte-for-byte identical** to the V3 archive already retained inside Surface’s Physical Cosmos continuation. Its separately attached `CONSTITUTION_V3.md` is likewise identical to the constitution inside that ZIP. This consolidation preserves that lineage, exposes its actual executable capabilities, and carries every unresolved V2/V3 obligation forward. It does not represent a newly completed N-chart physics engine or a new scientific result. [Audit receipt](../evidence/v3-consolidation-audit.json).

The existing native application and its selected PHANTOM/Oracle semantic ports remain the current product. The current turn adds bounded commission-text/harness work and a separate headless PolyIA adapter; it does not implement the full N-chart physics runtime. A generated work harness or a domain-coverage checklist can organize tests and record claims, but its successful generation cannot establish those claims. The original PHANTOM generator compiler, Oracle numerical harness and V3 seed are described precisely in [FOUNDATION_INVENTORY.md](FOUNDATION_INVENTORY.md). The complete mathematical gates and the compiler’s 23-domain review catalogue are in [MATHEMATICAL_ATLAS.md](MATHEMATICAL_ATLAS.md).

The native renderer has no browser/WebGL runtime. Android 0.1.1 actual-device launch remains unverified. Nothing in this consolidation claims execution on physical quantum hardware, a calibrated collider/accelerator, universal classical/quantum equivalence, or novel physics. [Native scope](PHANTOM.md), [startup repair](STARTUP_REPAIR.md), [current gate report](GATE_REPORT.md).

### Newly recorded V3 counterexamples

The unchanged seed admits a normalized three-amplitude vector into `complex_pairs`, declares two qubits and then rejects its own output at `decode_pairs`. The decoder ignores a changed `basis_order` label. XY chart construction accepts three-coordinate origins and nonfinite origins. Direct probability extraction accepts `[2,0]` and returns probability mass 4. A `scale=2` sine and a same-scale `energy` branch give squared amplitude 4 versus energy-labelled value 2 at the crest. All reproduction snippets and observed values are in `seed_counterexamples` in the audit JSON and [the foundation inventory](FOUNDATION_INVENTORY.md#8-v3-n-atlas-seed-implementation-and-counterexamples).

These observations do not invalidate the nine narrow original tests; they show that those tests do not close the full validation requirement. The native state codec already enforces stricter dimension, finite-number, normalization and interpretation-hash requirements. New adapters should preserve that discipline instead of inheriting the seed’s unchecked inputs. [Native state-record contract](PHANTOM.md).

## 7. Reproduce the preservation and numerical seed

From repository root:

```sh
python3 tools/materialize_foundation.py --output build/foundation
python3 tools/materialize_foundation.py --output build/foundation --check
```

If the destination already exists, run only `--check` or choose a fresh output. The materializer refuses replacement of the existing reference tree. These operations do not execute supplied archive code. After inspection, the original V2 and V3 checks can be run from their roots:

```sh
cd build/foundation/QUANTUM_ORACLE_V2_COMMISSION
python3 -B verify_inputs.py
```

```sh
cd build/foundation/QUANTUM_ORACLE_V3_EXTENSION
python3 -B -m unittest discover -s tests -v
python3 -B examples.py
```

Each code block starts from repository root before its `cd`. Python 3.11+ and NumPy are required for V3; the recorded audit used Python 3.12.14 and NumPy 2.3.5. Oracle additionally uses SciPy. The complete original PHANTOM/Oracle CLI examples, factory invocation and reference replay commands are in [FOUNDATION_INVENTORY.md](FOUNDATION_INVENTORY.md) and [FOUNDATION_REPLAY.md](FOUNDATION_REPLAY.md). New output destinations must be separate from read-only retained sources.

For the key malformed-state counterexample, from the V3 root:

```sh
python3 -B - <<'PY'
from atlas_quantum.core import complex_pairs, decode_pairs
record = complex_pairs([1, 0, 0])
print(record['qubits'])  # 2: encoder accepts three amplitudes
try:
    decode_pairs(record)
except ValueError as error:
    print(type(error).__name__, str(error))  # ValueError bad basis length
PY
```

This deliberately demonstrates original behavior; it is not a recommended adapter input. Additional probes are retained verbatim in the audit JSON.

## 8. Concrete continuation obligations

The next implementation stage should consume the immutable foundation through typed adapters and preserve the distinction between reference behavior and stricter integration validation:

1. **Admit a finite atlas schema.** Define chart/domain/observable/metric/edge/map records and budgets. Keep logical qubit IDs, physical qubits, couplers, basis indices and byte offsets in different schemas. Reject invalid dimensions, units, state norms, nonfinite inputs and inconsistent interpretation metadata.
2. **Implement witnessed transformations.** Begin with the same declared sine signal in value, spatial derivative, square and actual Fourier views. Bind parameters/phase/scales, numerical errors and source identity. Preserve loss when an inverse is unavailable.
3. **Add a controlled dynamical reference.** Use an explicit finite coupling law, analytic or independent numerical solution, conservation/dissipation accounting and perturbation/null controls. A complete graph of labelled edges is not a dynamics engine.
4. **Connect real domain fixtures.** Introduce licensed and hashed FITS/WCS and collision-event samples; preserve raw frames, units, detector/event metadata and uncertainty. Install/pin independent backends only with reproducible receipts and report missing inputs accurately.
5. **Connect actual discovery and compiler evidence.** Invoke PHANTOM’s real `synthesize_word`, typed runtime/compiler/factory and ledger interfaces where applicable. New atlas grammars need their own independent checking, held-out experiments and rejected candidates. Do not substitute a generated checklist for those executions.
6. **Implement native visualization and replay.** Feed verified observable samples and graph state into Surface’s native rendering layer. Distinguish numerical evaluation, draw submission/completion and observed device presentation. Retain frame/input/provenance identities and finite frame-work limits.
7. **Close integrated release gates.** Run the full V2/V3 paths from clean materialized inputs, with exact counts, commands, versions, hashes, tolerances, budgets and deviations. Leave unperformed or blocked stages visibly unresolved.

These are outstanding obligations, not promised hidden functionality. The inherited COMPOSER-first milestone and separately deliverable substrate/SDK contracts also remain obligations; an existing native Surface port does not retrospectively certify a complete COMPOSER harness. The original names **PHANTOM**, **QUANTUM ORACLE**, **N-ATLAS COMPILER**, and **SURFACE** retain their distinct roles.
